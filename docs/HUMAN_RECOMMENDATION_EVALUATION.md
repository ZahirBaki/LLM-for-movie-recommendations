# Local blind recommendation review

The development-only `/evaluation` page compares saved recommendation lists. It is separate from Movie Agent, has no public navigation link, and returns a not-found page outside Next development mode. Production RecommendationEngine, weights, catalog, embeddings and SVD are unchanged. Nothing is deployed.

## Open the page

From the project root, start the local evaluation service:

```powershell
.venv\Scripts\python.exe -m evaluation.scripts.human_evaluation serve
```

In another terminal, run the existing frontend development server if it is not already running:

```powershell
cd frontend
npm.cmd run dev
```

Open [the local review page](http://localhost:3000/evaluation). Use `localhost:3000` for the frontend: that is the service's allowed origin. The service binds only to `127.0.0.1:8013`. If the frontend uses another local port, use `--origin http://localhost:3001` when starting the service. The evaluation service port stays 8013 for this UI.

No OpenAI, TMDB metadata, provider, encoder or RecommendationEngine calls occur during human evaluation. Posters use existing TMDB image URLs and need internet access; titles, genres and overviews remain available without posters. Browser tests mock images and production API requests.

## Comparisons and input provenance

The default pair is **baseline vs `genre_votes`**, the isolated combined genre/vote/popularity reranker from the existing evaluation framework. All eight scenarios and the original ordered top-ten lists come from `evaluation/results/recommendation_quality.json`, generated by `evaluation/scripts/recommendation_quality.py evaluate`. No rankings are reconstructed or hardcoded in the review tool. Movies are joined by exact TMDB ID/title/year to the existing catalog and external snapshot. Catalog and external snapshot fingerprints must agree with the measured output.

Other existing variants can be selected by the researcher when starting the service:

```powershell
.venv\Scripts\python.exe -m evaluation.scripts.human_evaluation serve --challenger genre_aware --seed 42
```

Supported challengers: `genre_aware`, `popularity_confidence`, `vote_reliability`, `genre_votes`, `audience_proxy_filter`, `mean_story`, `strongest_story`. Baseline remains the other member of the pair. This configuration is not presented to the evaluator. Read `RECOMMENDATION_QUALITY_EVALUATION.md` for experimental scopes: notably the story aggregation variants omit SVD, so they do not isolate aggregation in collaborative scenarios.

The service consumes an existing evaluation output, never runs or deploys an experimental ranker. To change the measured output, run the existing offline evaluation CLI separately first. Existing review sessions retain their original movies, metadata, metrics and assignments when the service restarts or configuration changes.

## Blind assignments and human ratings

Each anonymous session receives a random seed and a shuffled, balanced assignment: baseline appears as List A in four scenarios and List B in four. A supplied `--seed` reproduces the assignments; the random anonymous ID still differs. The seed and algorithm mapping stay in private server files. Public session responses expose only favorites, movie metadata, List A/List B and submission status. They contain no algorithm identifiers, scores, variant names, diagnostic metrics or assignment seed. Movie ordering within each list is preserved.

Rate each displayed movie 1–5, or explicitly choose **Not seen / skip**. Ratings are keyed by scenario, side and TMDB ID, so the same movie can appear on both sides without ratings being confused. Choose Prefer List A, Prefer List B or About equal, and optionally add notes about genre, tone, audience, overall fit or variety. No name, email, account or IP access log is collected. Avoid personal details in free-text notes.

Drafts and the anonymous session ID are saved in browser local storage. Refresh resumes the review; starting the service again resumes server submissions. Each scenario is immutable after submission. Both the UI and service prevent duplicate saves, including concurrent clicks and retries. All movies require a rating or explicit skip, and the service validates IDs, side, order, integer rating range, list choice and note length. After completion, use **Start another anonymous review** for a fresh review of the service's currently configured comparison. A new browser context also starts a new anonymous review. There is no cross-device account recovery.

## Storage and export

Private session files, including assignments and pinned movie metadata, are written atomically under:

```text
evaluation/results/human/sessions/<anonymous-id>.json
```

The page never reads these files directly. Mapping exports are blocked by the service until **all eight scenarios** are submitted; there is no mapping endpoint during evaluation. Once complete, Export JSON and Export CSV download to the browser's usual downloads location. Requesting either export also saves a canonical completed JSON file under:

```text
evaluation/results/human/completed/<anonymous-id>.json
```

Completed exports contain scenario and anonymous evaluation IDs, algorithm identifiers, blind assignment, ordered TMDB IDs, individual ratings/null skips, overall preference, notes, source fingerprint and objective genre/diversity diagnostics. CSV has one row per movie/side; JSON groups rows by comparison. Local review storage is ignored by Git. There is no database.

Blinding protects the ordinary evaluation interface, not a researcher with filesystem access or knowledge of the configured pair/seed. A recognizable list may suggest its approach. Both sides may legitimately contain overlapping or identical movies; ties are valid. Administrative inspection can unblind a reviewer and should be postponed until completion.

## Analyze completed results

Analyze one or more completed exports using JSON **or** CSV for each session. Do not provide both formats for the same session; duplicate evaluation/scenario pairs are rejected.

```powershell
.venv\Scripts\python.exe -m evaluation.scripts.human_evaluation analyze evaluation_results\human\completed\<anonymous-id>.json --output evaluation_results\human\analysis.json
```

Replace `<anonymous-id>` with the actual file name. Multiple file paths can follow `analyze`. Completed exports from different measured-output fingerprints must be analyzed separately.

The script reports movie-weighted mean and median relevance ratings, equally weighted mean list ratings, rated/skipped counts, A/B wins and tie rates per algorithm, performance per scenario, preference agreement/disagreement with higher genre overlap, and mean genre diversity alongside human ratings. Win rate uses all comparisons, including ties. Genre/diversity agreement separately counts human ties and equal proxy values.

Skipped movies are never assigned a score. An entirely skipped algorithm has null mean/median ratings. Sample composition and unequal skip rates can bias summaries; repeated appearances and evaluations are not independent observations. Genre overlap is a proxy, not ground-truth relevance; genre diversity is a proxy for variety, not a human variety rating. The script makes no significance claims. No genuine human judgments have been collected by this implementation's synthetic tests.

## Validation

Focused offline unit tests cover reproducible balanced assignments, browser payload blinding, restart persistence, rating/ID/skip validation, concurrent duplicate prevention, completed-only exports, JSON/CSV mapping preservation, analysis means/medians/wins/ties, missing ratings, session isolation and local HTTP access controls.

Milestone verification: all 304 backend tests passed (17 new tests), TypeScript checks passed, the new desktop/mobile review browser checks passed, and both existing Movie Agent browser suites passed. The offline analysis CLI was also verified against synthetic completed browser exports. Production artifact fingerprints still match the prior evaluation inputs. Synthetic review files were removed after testing; no genuine human judgments or paid API requests were generated.

```powershell
.venv\Scripts\python.exe -m unittest tests.backend.test_human_evaluation
npx.cmd tsc --noEmit # from frontend
```

`tests/browser/check_human_evaluation_browser.py` tests the real local page and service with synthetic ratings, mocked posters and production API requests. Run the service with separate disposable storage (`--store .human-browser-test`) for that check. Never mix these fixtures with genuine human reviews. The existing Movie Agent interaction and presentation browser suites are also regression checks.
